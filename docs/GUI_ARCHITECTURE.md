# GUI architecture & conventions

## Layering: keep domain logic out of dialogs

GUI files should be presentation + wiring; the rules (validation, config
building, persistence, hardware orchestration) belong in a Qt-free layer that is
unit-testable without a screen. The domain layers are `src/core/`,
`src/hardware/`, `src/robots/`, `src/activities/`, `src/data/` — `core/` is not
the only one, which is why it is small.

Worked example: `src/core/skin_config.py` holds the skin-entry rules (node
lookup, validation, `build_skin_entry`, save/delete on the settings tree) as
pure functions over the plain `settings.data` dict. `SkinConfigDialog` calls into
it and keeps only widgets + `QMessageBox` text. Tests:
`tests/test_skin_config.py`. The same pattern applies to the other fat dialogs
(`session_panel`, `robot_panel`) if/when they are refactored.

## Layouts are `.ui` files

Author layouts as Qt Designer `.ui` in `src/gui/ui/`, compile with
`scripts/compile_ui.sh` (→ gitignored `src/gui/ui_*.py`, regenerated by CI which
globs `src/gui/ui/*.ui`). Never hand-build a layout in Python. Every control
gets a `whatsThis` (feeds the "?" help mode; `toolTip` is the fallback).

### The `monitor/` subpackage

Live monitor widgets (`src/gui/monitor/`) used to be hand-built in Python because
they are dynamic/QPainter. They now follow the `.ui` rule too:

- **Form/display panels** are `.ui`: `chamber_widget.ui`,
  `touch_tuning_panel.ui`. The Python class multiply-inherits
  `(QWidget/QGroupBox, Ui_X)` and calls `setupUi(self)`.
- **QPainter canvases are promoted widgets**. The painter class lives in its
  own module (`monitor/pressure_bar.py:PressureBar`) so the generated `ui_*`
  can `import` it without a circular import, and the `.ui` promotes a
  placeholder to it via
  `<customwidget><header>src.gui.monitor.pressure_bar</header>`. Promoted
  widgets are built by `setupUi` with the **default constructor**, so they take
  no required args. (The same mechanism promotes `HelpButton` from
  `src/gui/help_mode.py` in `observer_panel.ui`.)
- **Dynamic containers** (`skin_widget`, `robot_monitor_widget`,
  `robot_monitor_panel`, `organ_panel`) stay hand-built: they populate children
  in runtime loops, so a `.ui` would only hold an empty shell.
